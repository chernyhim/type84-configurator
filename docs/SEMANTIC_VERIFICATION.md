# Экспериментальная верификация семантики протокола (SEMANTIC VERIFICATION) Type 84

> **Важное методологическое правило:**  
> Все утверждения разделены по строгой шкале достоверности:
> - **`CONFIRMED`** — подтверждено минимум двумя независимыми экспериментами / взаимным совпадением разных подсистем;
> - **`OBSERVED`** — непосредственно зафиксировано в дампе, но полная семантика/динамика не доказана;
> - **`PROBABLE`** — устойчивая гипотеза, согласующаяся с архитектурой контроллера и несколькими фактами;
> - **`UNKNOWN`** — данные отсутствуют или недостаточны;
> - **`DISPROVEN`** — гипотеза опровергнута прямым анализом пакетов.

## 1. Подсистема `AA 12` — Key Remap Layer 1 (Базовая раскладка)

### 1.1. Верификация формулы маппинга (Hall Matrix $\leftrightarrow$ Remap Matrix)

Анализ 512-байтной таблицы сканкодов `AA 12` и взаимное сопоставление с адресами аналоговой матрицы Холла подтвердили системную связь:
$$\text{Remap Bank} = \text{Hall Bank}$$
$$\text{Remap Column} = \text{Hall Column} + 1$$
$$\text{Remap Slot} = \text{Bank} \times 16 + (\text{Column} + 1)$$
$$\text{Remap Byte Offset} = \text{Remap Slot} \times 4$$

Колонка 0 матрицы сканкодов зарезервирована для Numpad / служебных линий полноразмерного контроллера.

> Ранее в предварительной модели Backspace ошибочно связывался со слотом (6, 3).  
> Аппаратный capture `key_backspace_139mm.json` зафиксировал изменение байта по адресу `0x02E5` (741), что в точности соответствует **Bank 5, Col 12** матрицы Холла.  
> Формула $\text{Remap Col} = \text{Hall Col} + 1$ даёт **Bank 5, Col 13 (Slot 93)**, где в таблице сканкодов расположен именно сканкод Backspace `0x2A`!

### 1.3. Специфика "пустых" слотов с `00 00 00 02`
Слоты 28 (Minus), 42 (O), 56 (J), 70 (B), 84 (Space) имеют значение `00 00 00 02`.
* **Семантика:** В архитектуре контроллеров Sonix таблица EEPROM/Flash является переопределяющей (override table). Значение `00 00 00 02` (scancode = 0 при типе 0x02) означает использование **заводского ROM-дефолта** контроллера для данной координаты матрицы.
* **Статус:** **`PROBABLE`**.

### 1.4. Верификация WRITE-транзакции Remap L1 (`AA 22`)
В контролируемом эксперименте `Key A -> B` (дамп [`captures/experiments/remap_write_a_to_b.json`](file:///c:/KeyboardSoft/captures/experiments/remap_write_a_to_b.json)):
- **WRITE Opcode:** **`AA 22`** (**`CONFIRMED`**).
- **Фрейминг:** ровно 10 чанков (9 $\times$ 56 байт + 1 $\times$ 8 байт = 512 байт).
- **Терминатор:** отдельного пакета фиксации НЕТ. Завершается 10-м чанком (адрес 504), где байт `0x01` в слоте 126 выступает маркером фиксации (**`CONFIRMED`**).
- **Подтверждения:** контроллер выдаёт ровно 10 синхронных ACK `55 22 <sz> <addr>` (**`CONFIRMED`**).
- **Изоляция:** в переданном буфере среди 84 физических клавиш изменился строго байт сканкода клавиши A по смещению `0x00C9` (`0x04` $\to$ `0x05`, Slot 50) (**`CONFIRMED`**).
- **Обратимость:** после возврата клавиши обратно в конфигураторе read-back показал 0 различий с исходным состоянием (**`CONFIRMED`**).

## 6. Подсистема `AA 27` / `AA 17` — Hall Effect Switch Parameters

### 6.1. Статус параметров 8-байтной записи клавиши

| Слово | Байт | Параметр | Единицы | Статус | Доказательная база |
|:---:|:---:|:---|:---:|:---:|:---|
| **0** | `+0..+1` | **Actuation Point** | $0.01\text{ мм}$ | **`CONFIRMED`** | Аппаратная запись и read-back на Key A (`0x018D..0x018E`) через `NativeHidTransport` |
| **1** | `+2..+3` | **RT Press Sensitivity** | $0.01\text{ мм}$ ($0 = \text{OFF}$) | **`CONFIRMED`** | Физическая серия экспериментов RT Press на Key A (`0x018F..0x0190`), unexpected changes == NONE |
| **2** | `+4..+5` | **RT Release Sensitivity** | $0.01\text{ мм}$ ($0 = \text{OFF}$) | **`CONFIRMED`** | Физическая серия экспериментов RT Release на Key A (`0x0191..0x0192`), unexpected changes == NONE |
| **3** | `+6..+7` | **Flags / Mode** | raw uint16_le | **`UNKNOWN`** | Семантически не исследовано. Сохраняется verbatim без модификации |

### 6.2. Единая формула масштабирования
$$\text{raw} = \text{round}(\text{value}_{\text{mm}} \times 100)$$
$$\text{value}_{\text{mm}} = \frac{\text{raw}}{100.0}$$

Контрольные точки: `0.00` $\to$ `0x0000`, `0.10` $\to$ `0x000A`, `0.20` $\to$ `0x0014`, `0.50` $\to$ `0x0032`, `1.00` $\to$ `0x0064`, `1.40` $\to$ `0x008C`.

### 6.3. Аппаратная изоляция
Физически доказано, что модификация любого одного из трёх параметров затрагивает строго свои 2 байта и не требует изменения Flags или соседних полей.
