## 1. Транспортная структура буфера макросов (`AA 15` $\leftrightarrow$ `55 15`)

Таблица макросов и DKS (Dynamic Keystroke) считывается веб-конфигуратором с помощью команды **`AA 15`**:
- **Общий объём таблицы:** **400 байт** (`0x0190`).
- **Количество пакетов:** Ровно **8 входящих отчётов**:
  - 7 пакетов по 56 байт (`sz = 0x38`):
    - Чанк 0: адрес `0x0000` (байты `0..55`)
    - Чанк 1: адрес `0x0038` (байты `56..111`)
    - Чанк 2: адрес `0x0070` (байты `112..167`)
    - Чанк 3: адрес `0x00A8` (байты `168..223`)
    - Чанк 4: адрес `0x00E0` (байты `224..279`)
    - Чанк 5: адрес `0x0118` (байты `280..335`)
    - Чанк 6: адрес `0x0150` (байты `336..391`)
  - 1 хвостовой пакет по 8 байт (`sz = 0x08`):
    - Чанк 7: адрес `0x0188` (байты `392..399`)

```mermaid
sequenceDiagram
    autonumber
    participant Host as web.io.vision
    participant Dev as Type 84 Keyboard

    loop 7 чанков по 56 байт
        Host->>Dev: AA 15 38 [addr_lo] [addr_hi] ...
        Dev-->>Host: 55 15 38 [addr_lo] [addr_hi] [56B Data]
    end
    Host->>Dev: AA 15 08 88 01 ...
    Dev-->>Host: 55 15 08 88 01 [8B Tail Data]
```

## 2. Анализ данных базового состояния (Baseline Capture)

В сессиях [`read_01_initial_load.json`](file:///c:/KeyboardSoft/captures/experiments/read_01_initial_load.json) и [`read_03_reconnect.json`](file:///c:/KeyboardSoft/captures/experiments/read_03_reconnect.json):
- Байты полезной нагрузки пользовательских макросов с адреса `0x0000` по `0x0187` (392 байта) заполнены строго **`0x00`**.
- В хвостовом блоке по смещению **`0x0189`** зафиксирован байт **`0x01`**:
  ```text
  Offset 0x0188: 00 01 00 00 00 00 00 00
  ```
  Данный байт представляет собой флаг инициализации / версию таблицы макросов контроллера.

## 3. Гипотезы внутренней организации макросов

По структуре буфера (392 байта данных + 8 байт метаданных/терминатора):
1. **Фиксированные слоты макросов:**
   - 392 делится на:
     - 8 слотов по 49 байт;
     - 14 слотов по 28 байт;
     - 28 слотов по 14 байт;
     - либо динамический пул последовательности событий (Key Down, Delay, Key Up).
2. **Формат событий нажатия:**
   - В аналогичных контроллерах Sonix/BYK каждое событие кодируется 4 байтами:
     `[HID_Keycode, Action_Flag (Press=1, Release=2, Delay=3), Delay_MS (uint16_le)]`.
